# 轻舟 · macOS

SwiftUI / AppKit 原生客户端，提供订阅、节点、分流、诊断、菜单栏和私有网络。共享 Rust 核心处理业务，Mihomo 执行代理和 TUN，Go 适配器处理 aTrust 认证与 TCP 隧道。沿用旧版数据目录，不依赖 Node 或 JavaScript 后台。

## 应用、窗口与菜单栏

正式包名为 `轻舟.app`。版本和构建号定义在 `script/build_and_run.sh`，变化见 [CHANGELOG](CHANGELOG.md)。应用标识、数据格式和钥匙串服务保持兼容；图标源文件在 `design/app-icon-qingzhou-ink/`。

手动启动显示主窗口，系统登录项启动保持静默；关闭窗口继续后台运行，再次打开会恢复同一窗口和当前页面。Dock 图标可在设置或菜单中显示/隐藏，偏好持久保存。

菜单栏船形图标分别显示两类连接：个人 VPN 已连接时帆为蓝色，私有网络已连接时船体为绿色。通信中断显示未知，TUN 关闭时显示代理服务状态；普通检测错误不覆盖实际连接状态。

- 单击打开或收起 360 pt 面板，点击外部或 Escape 收起。
- 双击切换个人 VPN，三击不会额外切换。
- 右键、双指点击或 Control＋单击打开控制菜单。
- 面板独立控制个人 VPN、私有网络和授权资源接管。

按钮统一使用 `VPNButtonStyle`，44 pt 高、10 pt 圆角；深浅外观和两种窗口尺寸有离线布局检查。

## 个人 VPN 与退出

配置读取后，每次启动只尝试一次连接保存的具体节点。已有内核直接接续，手动断开、刷新或切换页面不再触发启动连接。自动连接不请求首次管理员安装或服务更新；需要授权时由用户明确发起连接。

已有内核运行时共用它，配置校验后在线加载。其他应用维护的连接受到保护，无法强制停止；界面可显示“验证当前连接”。网络修复和订阅探测等中断操作按连接归属限制。

菜单退出与 Command＋Q 共用等待和清理流程：等待已提交的操作，移除本应用的私有网络分流，确认认证 helper 结束，停止自己可管理的个人 VPN，最后关闭核心。等待操作超过 15 秒或清理未确认时保留应用并提示重试。退出阶段写入脱敏 `termination` 日志，其他应用维护的连接保留。

## 分流规则

规则表分别显示地址、匹配范围和 VPN / 直连出口，支持按出口筛选。添加时先选出口，再填域名、IP、网段或网址；无需手写底层格式。核心检查格式并返回匹配预览，保存失败时编辑弹窗保留输入。

填写示例、优先级与默认策略的区别统一见 [项目 README](../../README.md#如何填写分流规则)。已有 VPN 规则保留；直连规则保存在新增的 `directDomainRules` 设置中，旧核心快照仍可读取。

## 私有网络接入

目前支持 aTrust；EasyConnect 尚未接入。网关、账号和可选验证地址由用户配置。入口探测、证书核验、账号认证、授权资源和 TCP 隧道逐步显示真实状态，历史资源不当作在线会话。

系统信任、名称匹配且有效的网关证书可自动核验。未知自签名证书首次需要在“证书与连接详情”确认，随后按 HTTPS 主机和端口比对公开 SHA-256 指纹。证书变化须重新核实，过期或尚未生效的证书不能放行；登录和隧道握手继续校验。

记住账号和密码时，仅在认证成功后写入钥匙串；验证码、票据和会话保留在内存与私有管道。改密由服务器要求触发，明确成功后才更新凭据，细节见 [接入适配器 README](../../packages/company-vpn/README.md)。

快捷连接只在用户点击后创建连接意图。有保存账号和已核验网关时继续认证；缺少信息、证书确认或验证码转到私有网络页处理。取消、改网关、退出账号或退出应用撤销意图。普通启动不自动登录私有网络。

隧道连接、授权资源接管和业务验证分别控制：

1. 连接建立本机回环 SOCKS 出口，不请求预设业务地址。
2. 开启接管后，Rust 根据服务器授权的地址、协议和端口生成 Mihomo 规则，优先于局域网直连规则，同时保留原有外网出口、DNS 和自动路由。
3. 关闭接管只撤销分流，保留账号和隧道；再次开启复用当前连接。
4. 用户点击“验证”才请求业务地址，并核对实际 TUN 路由和私有网络出口；单纯内网直连成功不算通过。

业务验证失败保留连接；GPT 检测独立触发，外网检测失败不撤销私有网络。当前通道只支持 TCP，授权网段的 UDP 和未授权端口拒绝转发，不回退直连。

临时私有网络规则不写入旧版保留配置。断开、退出或崩溃恢复时移除本应用出口并恢复最新配置、保留节点组选择。共享内核被其他应用重启或重载后，等待 PID 和配置稳定至少 2.5 秒，再合并原有私有网络出口；不重新认证，也不代替其他应用启动内核。恢复清除旧业务验证结果，每分钟最多自动恢复 3 次。控制器超时不视为出口已删除，所有操作串行执行，恢复记录不含凭据并保护其他仍存活窗口的出口。

## 构建与预览

编译、测试、签名、公证和打包命令集中在 [开发指南](../../docs/DEVELOPMENT.md#macos)。默认输出 `dist/轻舟.app`，构建不启动应用且拒绝覆盖运行中的目标。

菜单栏预览替换 RPC、helper、钥匙串和登录项为假服务，使用独立偏好域；包内不含真实内核：

```sh
bash apps/macos-native/script/menu_bar_preview.sh --preview-reset
bash apps/macos-native/script/menu_bar_preview.sh --preview-login-launch
bash apps/macos-native/script/menu_bar_preview.sh --preview-certificate --preview-challenge
```

`--build-only` 只构建预览。预览旁的 `startup-report.json` 记录窗口和 Dock 策略；它不证明真实系统登录项已经注册。`script/verify_runtime.py` 使用临时数据检查协议。

构建与回归入口见 [开发指南](../../docs/DEVELOPMENT.md)，依赖准备见 [第三方依赖说明](../../docs/THIRD_PARTY.md)。真实联网、钥匙串授权、系统登录项、休眠恢复和不同输入设备仍需要按实际安装包验收。

## 网络切换与后台省电

网络断开再接入同一网卡、Wi-Fi 与有线网络切换、睡眠唤醒后，会等待物理网络稳定，再重新确认网卡配置和 DNS。恢复成功后丢弃旧路径上的个人连接，保留私有网络连接。等待网络、恢复中和恢复失败会明确显示，内核进程仍在时保留断开入口；连续失败后暂停自动重试，可点「重试网络恢复」。

网络检测优先使用系统通知，同时关注同一网卡的地址、网关和物理链路变化；忽略本应用造成的 TUN、DNS 变化。连续变化会合并，物理网络稳定约 3 秒后才恢复。手动断开会撤销自动连接意图，之后切网或唤醒不会擅自连接。系统通知遗漏时仍有低频兜底。

主窗口和菜单栏面板都不可见时暂停流量、日志刷新，重新显示时补取流量；断开后不轮询流量。可见时每 2 秒刷新，系统低电量模式下每 5 秒刷新。核心通过可唤醒等待取代每 100 毫秒的轮询，通常连接状态下每 5 秒维护一次，低电量模式每 15 秒一次，未连接时每 60 秒一次；网络恢复阶段临时加快检查。睡眠时暂停维护与自动订阅更新，唤醒后重新确认连接。相同状态不反复通知界面，请求完成后取消超时计时器。

这些检查频率说明后台工作量，不能直接换算成续航提升。真实网络切换、合盖唤醒和电池耗电仍需要用实际安装包测试。系统通知使用 Apple 的 [System Configuration](https://developer.apple.com/documentation/systemconfiguration/scdynamicstoresetdispatchqueue(_:_:)) 和 [电源状态通知](https://developer.apple.com/documentation/foundation/processinfo/powerstatedidchangemessage)。

新 App 启动前会核对系统连接服务版本。需要更新时，在总览和菜单栏面板显示「更新连接服务」，由用户点击并完成 macOS 授权后接续原节点；后台不会自动更新服务，取消授权保留原连接。新服务修复时区变化导致的进程身份误判。

版本为 0.6.3 / 2026101601，包含后台消息读取的逐轮内存释放修复。候选安装包由用户自行安装，未自动替换当前 App 或系统服务；长期内存、真实切网和权限行为仍需安装后验收。
