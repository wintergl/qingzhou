# 寻找最快的 ISP 链路（Mac 候选）


## 怎么用

1. 升级至 0.6.21 后，在首页点击“配置 ISP”（设置页也保留同一入口），填写供应商的 `hostname:port:username:password`，解析、核对协议并保存；测试时可以保持“走 ISP”关闭。
2. 保存 ISP 配置即可测试，可以保持“走 ISP”关闭，也可以完全不连接 VPN。未连接时会启动只监听本机回环地址的独立测试内核，不启用 TUN、系统代理或 DNS 监听。
3. 从侧栏进入“ISP 测试”独立页面；首页和节点页也可跳转，设置页保留测试入口。测试页可直接打开 ISP 配置。首页“走 ISP”开关可随时启用或关闭已保存的 ISP，关闭不会清除地址、账号和密码。未配置时打开开关会引导填写；重启后重新开启会先从钥匙串恢复密码。关闭不要求读取钥匙串。
4. 默认点击“测试并推荐”，优先从当前、收藏及上次成功的少量线路中查找，最多尝试三条，找到完整通过者即结束。单条测通即可开启省电维护，无需测完全部订阅；宽范围比较中已完整通过的线路也可以先使用，暂停后成绩继续保留。同名冲突节点不参与测试。
5. 默认概览展示当前线路、最近复核与性能测量时间。常用备选卡片不受下方订阅筛选影响，点击会定位到全部订阅中的该线路。需要更全面比较时，选择订阅后点击“重新比较”；“性能比较”展开已测范围内的综合、下载和响应榜单，“高级测试”保留补测、全量重测和持续测试。持续模式每条之间仍约间隔一分钟，用户可随时暂停。
6. 选中已验证线路后点击“使用这条线路”，软件先独立复核目标，再按需开启 ISP、连接 VPN、应用所选线路，最后确认业务连接的连通性、实际节点及出口 IP。系统授权按原有通道出现；不需要手动挑启动节点。已经使用且仍需确认的线路显示“复核当前线路”，不会重复重载或重建连接。未配置 ISP 时仍先填写配置；原分步准备保留在高级菜单。
7. 处理中可点击“取消连接”；等待当前请求或系统授权结束后，软件停止本轮操作并恢复原配置，保留原有 VPN；若原先未连接，则停止本轮新启动的 VPN。应用或最终复核失败时也执行恢复。恢复无法确认时明确显示异常并保留恢复记录，先检查恢复后才能再次连接。请求超时但结果未知时显示“结果待确认”，支持刷新状态及取消，不显示连接成功。

关闭检测窗口或主窗口不会取消任务，轻舟在菜单栏继续运行。重新打开可以看到原进度和有效结果，首页也会提示后台测试状态。“暂停测试”才会停止继续采样；当前网络请求完成或超时后停止。

性能测量超过 24 小时显示中性的“较早测量”，原分数及名次保留，不因此判定线路不可用。数据来自其他网络时明确标记，且不混入当前环境的性能榜单；ISP 配置与节点版本仍匹配的已验证线路可以先轻量复核使用，复核不会刷新性能测试时间。配置或节点版本不匹配时不能沿用旧验证，需要重新测试。比较切换收益时，两条线路需有同一轮测量，旧缓存无法证明同轮时会提示补测。

2026-10-29 前一轮修订已将刷新时间从 10 分钟放宽到 24 小时，核心 `suggestedRefreshSeconds` 返回 86400。当前进一步将其作为性能补测窗口，时间标记与名次分开；重启仍按原测量时间计算。下方历史版本中的 10 分钟/600 秒及全量基准要求仅对应当时实现。

结果会写入本机受限权限缓存。完全退出轻舟会结束后台任务；重新启动后，仅在 ISP/分流配置、订阅及网络指纹均匹配时作为当前环境的参考复用。重新启动不会刷新观测时间，也不会自动恢复持续测试，需要用户再次开启。缓存不保存密码、代理服务器地址或原始生成配置，只保存测试结果与配置/网络摘要。

当前排名使用各节点的最新观测，不取历史最高分；新一次失败会替换当前排名中的成功状态，但每次完整测量都独立归档，旧成功和旧失败均长期保留。累计观测次数不代表平均分或一直成功。配置或网络环境变化后，不把旧环境的结果混进新排名。

关闭静态 ISP 不影响独立测试；未配置 ISP 时，页面提示先保存配置。原有机场连接及节点测速功能继续保留。

## 测什么

路径为：本机 → 被测机场 → 静态 ISP → 同一个测试站点。

- 综合响应：3 次独立连接请求的中位数，包括连接、TLS 和测试站点响应，不是 ICMP ping，也不是单独的“机场服务器到 ISP”往返时间。客户端初始化不计入该耗时。
- 波动：上述响应样本的最大值减最小值。
- 短下载：2 次 512 KiB 下载的有效速率中位数，计入建立连接与接收完整响应的时间。必须接收到准确的字节数，不把错误页、短响应或超时视为成功。
- 成功次数：分别显示响应测试和下载测试成功次数，不冒充严格的丢包率。
- 出口：每条组合都查询实际出口 IP；配置了“预期出口 IP”时必须一致；连接推荐链路前还会复核一次。

每条链路下载正文约 1 MiB，另有少量请求、协议和 IP 查询流量。持续模式每轮间隔约 1 分钟，正文流量最多约 60 MiB/小时；可以随时暂停。界面会按可测试节点数量提示总量。短样本用于本轮比较，不能证明持续带宽上限，也不保证该排名适用于所有网站或其他时段。需要更偏向交互响应时可选择“响应优先”。

测试使用 Cloudflare 的公开下载接口（0 字节和指定字节数请求），接口设计见 [Cloudflare Speedtest 官方文档](https://github.com/cloudflare/speedtest/blob/main/README.md)。出口查询使用 ipify。测试站点不可达时会如实失败，不把其他路线冒充为链式测试。

## 综合分怎么算

综合模式给下载和响应相同的重要性，同时考虑波动：下载权重 45%，响应权重 45%，波动权重 10%。先把三个指标分别转换成 0～1 的效用值，再用加权几何平均计算 0～100 的综合分：

```text
D = 短下载速率（Mbps）
L = 综合响应耗时（ms）
J = 波动，即响应样本最大值减最小值（ms）
综合分 = 100 × (D / (D + 10))^0.45
             × (150 / (150 + L))^0.45
             × (30 / (30 + J))^0.10
```

几何平均会降低明显存在短板的链路得分，较快的下载不能无限补偿很高的延迟。固定参考点 10 Mbps、150 ms、30 ms 避免新加入一个极端节点后其他节点的分数整体变化。它们是产品默认参数，未经真实使用体验校准；综合分不是网络质量百分比或测速精度承诺。

综合模式要求下载和延迟大于零，波动大于或等于零，且指标完整、有限、所有测试均通过。缺失、无效或部分成功的结果显示“未评分”，不参与综合推荐。排序使用未舍入的分数，展开详情后界面显示一位小数；分数相同时先比较延迟，再比较下载。连接时按同一策略在核心重新确定推荐结果，不在 Swift 界面另算一遍。

例如，100 Mbps / 1200 ms / 80 ms 波动的链路会低于 20 Mbps / 150 ms / 15 ms 波动的链路，避免“只看下载快”导致推荐高延迟连接。这是规则示例，不是用户真实节点测量结果。

## 对正在使用的连接有什么影响

静态 ISP 的业务出口继续通过 `VPN` 选择器连接当前机场。扫描使用另一个独立选择器及 ISP 出口副本，监听地址仅为本机回环地址。未连接 VPN、关闭 ISP 或现有连接由旧版维护时，使用单独的测试进程、随机控制端口、控制器密钥和临时运行目录，结束测试或正常退出时停止进程并清理临时配置。扫描只改变自己的机场选择，不改变业务连接当前的机场，也不改变系统 DNS 或路由。

后台测试与其他节点检测共用互斥检测锁；只在实际采样时暂停自动站点检测及自动订阅下载调度，等待下一轮时不长期占用检测入口。已有后台下载若完成并改变订阅，会使本轮结果失效。正在使用的业务流量仍可能影响测速，结果只代表测量时的实际情况。

只有点击“连接推荐链路”或“复核并连接”才会变更业务机场。所有推荐应用前都会做一次轻量响应检查和实际出口 IP 复核；复核失败不切换。复核只确认当下连通性与出口，不代表重新测过吞吐，也不刷新原测量时间。持续测试时也可连接有效的缓存推荐，软件会等本次采样结束，复核出口、切换连接，然后继续后台测试。应用时重建原有个人代理连接，使其经新机场到同一 ISP；直连和私有网络连接保留。出口复核失败时不切换；配置应用失败走现有事务回滚。

本轮仍只支持 TCP；静态出口相关代理 UDP 不会旁路到机场或直连。密码存储与运行文件权限沿用[静态出口说明](STATIC_ISP_EXIT.md)。

## 失败节点冷却与自动重试

未指定模式时默认使用积累测试。失败节点首次冷却 1 分钟，连续失败依次冷却 2、4、8、16、32 分钟，之后最长 1 小时。冷却结束后，即使服务器 IP 未变化，也重新允许测速；检测到服务器地址或 IP 集合变化则可提前重试。DNS 查询失败不会延长冷却期。成功后清除连续失败计数。

持续测试运行时会自动重试冷却结束的节点；积累模式在下一次启动时补测，暂停或退出后不会偷偷发起测速。“全部重测”绕过冷却期，方便手动复查。低分但完整通过的节点不会进入失败冷却；节点选择器故障、客户端初始化失败和用户取消也不作为节点质量失败记录。旧版无冷却截止时间的失败记录按原测试时间加 1 分钟迁移，不重新计时。

失败计数与重试时间随当前缓存保存，重启不会延长冷却；缓存只存服务器地址和 IP 集合摘要，不保存原始地址或密码。ISP 或分流配置变化后不沿用旧配置的失败冷却。

## 长期测试记录

“ISP 测试”页展开“长期测试记录”，可查看测量时间、当时结果、响应、下载和综合分，并标注是否属于当前环境。每页 50 条，可加载更早记录；测量期间可点击刷新记录。历史按测量时间倒序，不把旧观测混成当前成绩。

核心新增只读 RPC `chain-scan:history`，接受可选 `before` 游标及 `limit`（1～200），返回 `records`、`nextBefore` 和 `hasMore`。`chain-scan:get` 每条结果新增 `requiresRefresh`、`testedAt`、失败时的 `nextRetryAt`，`stale` 仅表达当前环境不匹配。`suggestedRefreshSeconds=600` 是建议刷新间隔，旧字段 `validitySeconds` 返回空值。Windows/iOS/Android 当前调用方未使用这些 ISP 测试字段，本轮没有新增对应界面。

## 日常自动维护：省电抽测

手动完成当前环境全部启用订阅的全量测试后，才自动维护已有成绩；不自动测试新增节点或自动开启一轮完整扫描。网络或 ISP 等环境变化后，旧成绩仍可在历史中查看，新环境需再次手动全量测试建立基准。订阅变化时，只沿用相同环境、身份和订阅版本仍匹配的成绩，新节点由用户手动补测；若没有任何匹配成绩则需要重新建立基准。旧版本完整缓存只有在当前节点均有匹配记录时才可作为基准。

自动维护每两小时最多启动一批，每批最多测三条已有成绩，优先当前线路、综合推荐，再选择最久未测线路；批次时间保存在缓存中，重启不会绕过限制。每条测试仍使用原有完整采样和出口核验。睡眠、低电量模式、电池供电或 macOS 未能确认供电来源时暂缓；手动测试不受电池限制。网络事件或唤醒后等待两分钟，期间自动测试不会启动或继续。

自动测试连续两条失败就结束当批；失败观测单独记录并标记环境待确认，已有成功成绩保留但视为历史参考，不能冒充新鲜结果。下次批次先进行一次短小的普通网络连通性检查，失败则继续等待；检查成功也不代表 ISP 或机场一定可用。自动测试不会切换业务连接，历史成绩应用前仍需原有出口和连通性复核。既有 intervalMinutes 字段保留以兼容旧调用方，但不再控制自动抽测频率。

### 24 小时有效期下的进一步省电（2026-10-29 后续源码）

自动批次连续完成采样后退出，取消条目之间一分钟的固定等待，尽快释放独立测试内核；每条线路仍需三次响应、两次完整短下载及出口核对。手动持续测试原有的一分钟间隔保留。

Mac ISP 页面只在窗口可见且未睡眠时轮询。空闲时接电每 15 秒读取一次，电池供电、供电未知或低电量模式每 30 秒读取一次；测试运行中分别为 1 秒和 2 秒。隐藏或睡眠会取消轮询任务，窗口重新可见或唤醒时立即读取一次结果。页面轮询不驱动后台测试。


## ISP 连接异常时自动切换备用（2026-10-30 源码修订）

日常线路池保留当前线路，并从每个启用订阅各选两条已完整通过测试的备用。两个订阅都有足够成功成绩时，共四条备用；当前线路不占所在订阅的备用名额。没有足够成功成绩时只保留实际通过的数量，不把未测、失败、身份冲突或订阅版本已变的节点补进来。已有备用优先保留，缺额按综合成绩补齐；手动全面比较后可按新成绩重建。

轻舟维护的 ISP 连接连续三次出现出口异常时，后台复核备用，优先尝试另一订阅。备用的连通性与 ISP 出口都通过后才切换，并再次确认实际连接。某条备用复核失败后继续尝试其余备用；全部失败时保留当前配置和线路，交回已有网络恢复流程。实际切换后确认失败则使用原连接事务恢复，恢复无法确认时保留恢复记录，不声称成功。

单次波动、DNS 故障、控制器异常、睡眠和换网稳定期不会触发备用切换；主动断开、改配置或取消操作会阻止旧任务继续应用。自动切换只处理已连接且由当前轻舟维护的 ISP 连接，不主动启动 VPN，不回退到直连。两次自动尝试至少间隔五分钟，冷却在重测和重启后仍保留。

自动切换与省电测速维护分别调度：省电测速仍需显式开启、仍保持每两小时每批最多三条的预算；连接保护不依赖测速维护开关，也不因电池供电而停止。备用复核没有下载测速，不更新原性能成绩或测量时间。

Mac 日常页显示备用所属订阅，并以两列展示四条备用。新增返回字段仅补充测试行的 `subscriptionId`、`subscriptionName`；旧 `routine` 数组字段保留，Windows 使用动态 JSON 可读取新增数量，iOS/Android 的移动核心调用不变。本次自动换线调度属于桌面核心，未增加移动端后台换线能力。


## 配置置顶与可见的备用切换（2026-10-30 源码修订）

Mac 首页最上方显示 ISP 配置、开关和备用线路入口；ISP 线路页也将配置置于顶部。日常页优先展示当前线路和按订阅分组的备用，点备用卡片即可发起复核与切换；完整排名通过“性能比较”进入。

手动与自动换线共用顶部状态区：显示原线路 → 目标线路、复核/切换/确认出口三个步骤及最终结果。复核过程中保留当前线路和全部备用，目标卡片高亮；处理期间阻止重复操作。成功或失败结果保留到用户收起，失败可重试或直接选择另一条备用。

连接状态新增可选 `automatic`、`previousNodeName` 字段，修复 Mac 只接收界面自己发起的操作、过滤后台自动换线状态的问题。主动断开后使旧状态失效，迟到的成功通知不能覆盖断开结果。

线路复核现在区分目标响应请求失败、ISP 出口查询失败、返回结果无效和出口不匹配；网络错误不会附带请求 URL 或凭据。切换失败在页面内展示具体原因，不再用全局“操作未完成”弹窗阻断备用操作。已有复核、真实出口确认和恢复流程继续执行。
