## 自行测试

1. 自行安装候选包后，在“节点”选择一个可用机场节点。
2. 打开“设置 → 静态 ISP 出口”，粘贴供应商提供的 `hostname:port:username:password`，点击“解析粘贴内容”。密码中的冒号会保留；IPv6 地址使用分开的服务器、端口字段填写。
3. 核对供应商实际提供的协议。解析默认 SOCKS5，也可选择 HTTP 或 HTTPS。用户名、密码均留空可用于供应商支持的白名单模式；链式连接时供应商看到的接入来源是机场出口，白名单必须与之匹配。
4. 可选填写“预期出口 IP”：填写后检测会比较实际 IP；不填写只显示查询结果，不把未知 IP 宣称为已核对正确。
5. 打开“经机场连接静态出口”，点击“保存并应用”，连接 VPN，再点击“测试已保存出口”。返回通过这条链查询的实际 IP 和查询耗时。
6. 换一个机场，再测一次；预期最终 IP 仍保持为购买的静态出口。查询耗时包含 HTTPS 建连和查询耗时，不是纯网络 ping。
7. 关闭开关并保存，确认原有机场连接仍可使用。未购买、未配置或关闭静态出口时，原有连接方式保持可用。

## 行为与限制

- 连接顺序为设备 → 当前机场节点 → 静态 ISP → 目标网站。开启后，“总览”和菜单栏会提示静态 ISP 及机场前置。
- 只替换原本走代理的流量；局域网、国内与自定义直连规则、私有网络出口继续按已有规则工作。微信先遵循自定义规则和国内直连；开启兼容回退时，其余微信连接优先直连，只有直连健康检测失败后的代理回退使用静态 ISP，不会仅因开启 ISP 就让整个微信走代理。
- 邮箱大师默认启用应用直连，包含海外邮箱；自定义代理与私有网络规则仍优先，静态 ISP 不接管已命中直连的邮箱连接。可关闭“邮箱大师优先直连”恢复常规分流。原有 8081 兼容只控制 HTTP 嗅探，不承担分流开关的作用。
- 启用后静态出口不可用就报错，不静默退回机场或本机出口。先关闭静态出口，才能把机场选择切换为 DIRECT。
- 保存配置会重建已有的个人代理连接，使其重新经过新出口；保留直连和私有网络连接。配置校验或重载失败时回滚原配置。
- 目前静态出口链只承诺 TCP。对应代理规则下的 UDP 被拦截；不适用于尚未验证 UDP 支持的游戏、语音和 QUIC 场景。
- 检测使用单独的本机入口，固定指向静态出口，不被默认直连规则影响。正常连通性、站点检查及后台出口健康检测也使用最终出口；节点测速/节点风险检测仍用于评估机场节点本身。
- 密码长期保存在 Mac 钥匙串，不进入 settings.json，也不进入源码、安装包或命令行参数。Mihomo 运行时需要凭据，其生成配置及事务恢复文件由现有原子写入机制以 0600 权限保存；不能把运行目录作为公开诊断包分享。
- 本轮完成 Mac 的配置界面、钥匙串接入和测试入口。Windows 没有新增填写界面与凭据恢复；iOS、Android 没有新增界面，若手动移入启用了静态出口的设置，会明确拒绝连接，避免忽略设置后从机场出口访问。未配置的各端沿用原路径。
